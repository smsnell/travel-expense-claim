## Smallest suitable architecture

Propose a local Python command-line implementation under `skills/travel-expense-claim/`, invoked by a thin Skill. Use standard-library `Decimal`, date/time, CSV, JSON and hashing; pin `jsonschema` for Draft 2020-12 validation and a PDF text reader / XLSX reader only as needed for the inspected PDF/XLSX formats. No hosted service, database, paid API, or runtime model is currently justified. Python/jsonschema and pinned PDF/XLSX readers are now available in the project virtual environment.

Keep four small responsibilities, without a generic workflow framework:

1. **Acquire and normalize:** supported read/export adapters attempt all five locations for each fresh run. Retain native bytes and any text actually interpreted, record versions and unavailable portions, inventory pages/tabs/records, and normalize records with locators and original lexical values. Fail closed on incompatible layouts. Access configuration contains locations, not case answers. Optional agent-assisted extraction produces validated local structured inputs with exact source references; never generated business responses.
2. **Apply batches:** deterministic state reducer admits only delivered records, validates identities/actors/packets, calculates money, tracks obligations, and reconciles Finance events. Use explicit dependency checks for evidence, calculations, decisions, requests, and cancellation effects. Preserve arrival observations separately from unique event effects. Maintain revision history and reasoned invalidation, not a single overwritten case object.
3. **Seal and render:** assemble the public snapshot plus narrowly documented supplementary `trips`, `permits`, `decisions`, `obligations`, and `repair_items`/history fields as needed. The schema allows extra properties but does not validate them: add focused semantic checks. Its `requests` array describes monetary Finance requests; do not squeeze evidence-repair drafts into that shape. Render current CSV, report, and local queue from the same retained state. Write manifest before sealing snapshots; bind relative paths to exact bytes; publish outputs only after checks pass.
4. **Verify/replay:** separate business calculations from integrity verification. Reuse retained inputs only under explicit replay. Check exact prior hashes before resuming; deduplicate event effects while retaining redelivery provenance. Changed recomputation gets a linked new run. Recover only from complete retained history, recording actual reconstruction time without inventing original execution times.

**Policy input mode:** default to a fresh supported Notion read. Provide an explicit `--policy-file <path>` option (initial supported format: UTF-8 Markdown, such as `policy/POL-2026.2.md`) for operator-supplied copies. Still attempt all five native URLs on a new run. Record the unavailable native policy portion separately from the manually read copy in `sources.json`, with distinct source IDs, native origin URL, local origin, observed read time, version, exact retained bytes/hash, provider and unknown export time where appropriate. A supplemental `acquisition_method: manual_file` must prevent the copy being mistaken for a successful native read. Validate nonempty policy content, declared revision and required sections; flag apparent truncation/conflict. If both native and manual content exist, compare and report differences; do not silently choose conflicting rules. Bind decisions to the actual policy bytes used. Replay uses that run's retained file explicitly. Report manual-input provenance as a native-source limitation, even when processing the supplied records succeeds; the mode is not offline replay or proof of complete native access. No auto-fallback to a bundled file.

The command surface is `run`, `resume`, `replay`, `verify`, and `recover`; exact commands and exit statuses are in README.md. G1 implements `run`/`verify`; the other commands explicitly fail as unimplemented. A full-run status is separate from individual case status. A valid run can report unresolved cases; missing sources or unimplemented branches must be visible as partial coverage, never successful completion.
